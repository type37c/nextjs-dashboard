# MC-5C（確証・事前登録あり）：二時定数のLIF中継による振動子間の計算を確証し、T7中継の不利を切り分ける

## 結論

**事前登録したP1〜P6はすべて達成された**（未使用の20回路380〜399、計画のレビュー承認後にプロトコルを凍結 `e602b29`、一度だけ評価）。

T7の記憶集団 → 遅い中継S・速い中継F（LIF） → 出力Rという3段の振動子回路で、**Rの実際の発火による判断が`both` 0.707**（20回路すべてで0.68〜0.74）に達し、遠い過去と直近の両方の情報を使っていることを、選び直した対照で確かめた。

- **LIF中継では、Rへの実装による損失はない。**中継の発火から外部で判断した値（0.68〜0.69）と、Rの実際の判断（0.70〜0.71）がほぼ同じ。
- **T7中継は、中継の段階で情報を失っている。**中継の発火から外部で判断しても0.472。特に速い役割（F）の相関が0.42で、LIF（0.63）より大きく低い。遅い役割（S）でも0.67対0.78〜0.79。
- **不応期をそろえても差は残る。**LIFの不応期をT7と同じ32にしても、`both`は0.698で、LIFの不応期8（0.707）とほぼ同じ（差+0.009）。T7の不利は、不応期の違いでは説明できない。
- **ただし発火予算はそろっていない。**LIF32とT7の発火率は、Sで18.9対12.4（約1.5倍）、Fで4.5対9.1（約0.5倍）である。「発火予算では説明できない」とは言えない。発火率をそろえた比較は、別の探索として設計した（[PLAN_RATE_MATCHED.md](PLAN_RATE_MATCHED.md)、未実施）。

## 何が確証されたか、何が確証されていないか

**確証されたこと（この課題・この生成規則の回路・オフラインに決めた重みの範囲で）：**

- 記憶を保持する振動子群（T7）、時間スケールの違う2つの受け手（遅い中継・速い中継）、判断する振動子（R）という役割の分担で、**外部の判断器なしに、Rの発火が、遠い過去と直近の両方に依存する判断を行う。**
- 両方の受け手が、それぞれの役割で必要である（片方なしで選び直すと0.5、役割を入れ替えると0.5）。
- 受け手が1つのとき（中継なし）は成立しない（0.497）。

**確証していない・主張しないこと：**

- **T7に固有の優位性。**この回路で、T7は受け手（中継）としてLIFに大きく劣った（副次、−0.189）。記憶集団としてのT7の役割と、LIFを記憶集団にした場合との比較は行っていない。
- **局所学習。**中継とRの重みはオフラインのリッジ回帰、格子は検証データで選んだ。
- 汎用のAI、実機での省電力。
- 時定数（1000・100）や課題を変えた場合への一般化。

## T7中継の不利について（未解決の論点）

- 中継の段階での損失は、速い役割で特に大きい。これはMC-1b・MC-2の「T7は直近の時刻の精度が低い」と一致する。
- 候補の一つは、元のT7モデルの仕様（位相が負になると2πの手前に巻き戻り、余分な発火を生み得る）である。Issue #125 の指示どおり、これはMC-5Cの判定に入れず、位相を0で止めたT7を**別の素子として扱う小さな探索診断**で調べる（未実施）。その結果で、MC-5Cの評価方式や結論は変更しない。

## レビュー対応（Issue #129）

事前登録した主判定P1〜P6と、保存した評価データは変更していない。

### 1. 発火予算の比較の解釈

- 計画書（PLAN.md、凍結済みのため修正しない）と最初の報告では、LIF32を「予算をそろえた比較の相手」と書いたが、**そろえたのは不応期だけで、発火率はそろっていない**（上の表）。報告の表現を、「不応期を32にそろえても、現在の動作点の探索ではLIFが有利」に限定した。
- 発火率をSとFそれぞれ近い範囲に制約したT7とLIFの比較を、別の探索として設計した（[PLAN_RATE_MATCHED.md](PLAN_RATE_MATCHED.md)）。発火率をそろえても情報量が等しくなるわけではないことも、そこに明記した。T7の負の位相速度の巻き戻りの診断とは区別する。

### 2. 監査の範囲と、独立した照合

これまでの監査（`audit_mc5c.py`）は、人工の入力で乱数種・窓・ラベルの計算を確かめたもので、確証の実行結果そのものは照合していなかった。次の2つを追加した。

|検査|内容|結果|
|---|---|---|
|[crosscheck_mc5c.py](crosscheck_mc5c.py)|(1) 凍結したprotocol.jsonのハッシュが現在のソースと一致し、回路・条件がrows.jsonと一致する。(2) 凍結した乱数種から評価ストリームを作り直し、別に書いた総当たりのラベル付けで、保存した判断の行（ストリーム・履歴の種類・ラベル）と一致する。(3) 20回路×Rの9条件すべてで、保存した判断ごとの予測から、mc4・verify_mc5cの採点コードを使わずに再計算した正答率・2つの対比・`both`・誤警報率が、rows.jsonと一致する（誤差1e-12）。(4) その値からP1〜P6を別のコードで再計算し、verdicts.jsonと一致する。|**PASS**|
|[replay_mc5c.py](replay_mc5c.py)|回路380と399について、凍結したコードと乱数種で、集団 → 中継 → R の物理計算を全条件で再実行し、保存した判断ごとの予測とrows.jsonの全数値が完全に一致するかを比べる。|**PASS**（2回路とも不一致0件、`results/mc5c_relay_confirm/replay.json`）|

**監査の範囲：**crosscheckは、保存した予測からスコアと判定までの独立な再導出であり、物理計算の再実行ではない。物理計算の独立な再実行は、replayで行った2回路（20回路中）に限られる。
