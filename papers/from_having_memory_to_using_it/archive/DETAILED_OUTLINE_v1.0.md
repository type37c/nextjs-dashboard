# From Having Memory to Using It: A Research Agenda for Memory-Dependent Computation

改訂版詳細骨子 v1.0 — 2026-11-06

著者予定：Keisuke Ohtani。本文は英語で執筆する。本書は構成を確認するための日本語の詳細骨子であり、導入の下書きには進まない。

## 執筆契約

**中心となる立場：** 履歴依存系を評価するときは、過去の区別を保持できるかに加え、その区別を、許された観測・操作・時間・資源の下で次の行為に利用できるかを測るべきである。読み出し、準備選択、更新制御、他の系からの利用を「記憶の管理操作」として明示し、失敗の所在と費用を比較する研究課題を提案する。

**主な対象：** 実行中の状態が次の処理を左右し、基板の更新則を自由に学習し直せない系。学習可能な更新則を持つモデルへの適用は比較・検証課題とする。

**貢献：** 記憶の利用を分解する概念、実験による具体例、読者自身の系で使う測定手順。新しい万能モデル、知能の必要十分条件、T7の優位性、既存の記憶研究に対する優先権を主張しない。

**背骨：** 読み出しと準備選択／更新と保持の両立／経験の共有、という三つの壁。管理の動詞は各壁で必要になる操作として導入する。普遍的な知能の発達段階とは扱わない。

**証拠の扱い：** 以下の数値は、今回確認した固定コミットの報告・保存集計に基づく。E7-Dは計画・集計も確認し、OTB21は保存した全試行から主要集計を再計算した。新しいシミュレーション、外部研究者による追試、全系列の独立再検証を行ったわけではない。

**続編との境界：** 本稿の付録は利用可能性を診断する基本手順。リセットが何を隠すかの体系的な比較実験・独立した測定法論文は続編に残す。

## 0. Abstract — 要旨の設計

**主張：** 記憶容量や課題正答率だけでは、保存された履歴が利用できない理由を特定できない。利用を可能にする操作と費用を研究対象にする。

**使う証拠：** 三つの壁の事例を一つずつ示す。読み出し・選択の改善、更新と保持の両立に要する待機、接続中の経験利用。MC系列の中継での不利も一文で予告する。要旨では異なる課題の数値を並べて単一の性能向上物語にしない。

**想定される反論：** 「既知のメモリ管理を言い換えただけではないか」。概念名ではなく、同じ正答率でも異なる失敗原因を識別でき、次の介入を選べることを評価対象に置く。独自性の文献調査が終わるまでは「初めて」と書かない。

**要旨の順序：** 問題 → 立場 → 限定した事例と不利な結果 → 検証可能な研究課題 → 付録の手順。

## 1. The gap between retaining history and using it

**主張：** 過去の情報が内部状態に残ること、その情報が許された出力から読めること、読み取った情報で次の処理に成功することは、別の問いである。知能全体を定義する前に、この差を計測可能にする。

**使う証拠：** MC-4Xの探索を短い動機例に使う。同じ発火列でも、受け手と読み出しの時間スケールを変えると利用できる情報が変わった [MC4X]。詳細は第4節へ送る。basin-mv.comの記憶・位相・発火の教材を補助デモとして案内し、教学用の操作画面自体を研究結果の証拠にはしない。

**想定される反論：** 「RNN、適応ニューロン、状態空間モデル、KVキャッシュも実行時の状態を持つ」。その通りであり、これらを対象から除かない。LIFが履歴を持たない、固定重みの推論には状態がない、継続学習は誰も扱っていない、といった導入は使わない。

**節の着地点：** 「何を記憶しているか」に加えて、「どの履歴を、どの観測と操作で、いつまでに利用できるか」を問う。

## 2. Scope, limits, and conditions that would defeat this position

### 2.1 証拠を見る前に明記する限界

**主張：** 本稿の立場は、特定の操作の有効性と、診断枠組みとしての有用性に分けて検証する。成功結果を何でも管理操作の成果に分類する循環論法を避ける。

**使う証拠と確認範囲：**

- E7-D：固定した既知の5回路、二候補の準備選択、未使用入力群。読み出しの重みは外部で学習。新回路への一般化や自己学習ではない [E7D]。
- MC-5C：特定の生成規則からの未使用20回路。主判定はLIF中継を含む役割分担。T7比較は副次 [MC5C]。
- MC-4X・MC-5D：各5回路の探索。因果機構の候補を絞る結果であり、普遍法則の確証ではない [MC4X] [MC5D]。
- OTB21：保存済みの8つの学習記憶、4位相、旧・新の文脈の組合せ。合成初期条件を用いた固定方策の追加境界評価であり、自然な運用履歴の無作為標本ではない。guardはe/sを直接読む外部比較器 [OTB21]。
- OTB22：人工的な一つの関係鎖を持つ3所有者、8位相×2座標表示。対象同一性・文脈・刺激時刻などは設計者が与える [OTB22]。
- すべて数値シミュレーション。実機の速度・消費電力・大規模環境での優位は未実証。異なる系列を、一つの統合AIが達成した能力として合算しない。

**想定される反論：** 「外部制御が答えを作っているのではないか」。各実験で情報の入口と外部処理を図示し、基板、読み出し、制御器、採点器を分ける。診断用の完全状態や正解を、実行中の選択器へ渡していないかを確認する。

### 2.2 反証可能な予測と、撤回する主張

以下は**今後検証する予測**であり、既存実験で成立済みとは書かない。適用する課題・モデル群、最低限意味のある効果、費用上限、統計手順を取得前に固定する。

| 対象と予測 | 比較・測定 | 反する結果が出たときに撤回・縮小するもの |
|---|---|---|
| H1：明示した固定基板の課題群で、状態に応じた管理は時間を合わせた固定方策より獲得・保持の両立を改善する | 同一履歴、候補集合、学習予算、総期限で、待ち時間を十分調整した固定方策と比較 | 差が消えれば、その課題群での状態依存管理の実用的優位を撤回する。OTB21の結果を効率優位へ拡張しない |
| H2：読み出し・選択・候補不足の分解は、新しい条件で有効な介入を予測できる | 診断で失敗原因を推定してから、読み出し改善と候補変更を別々に実施。単純な成功率・経過時間による予測と比べる | 指摘した箇所への介入が改善を予測せず、簡単な指標にも追加価値がなければ、診断枠組みとしての価値を縮小する |
| H3：異なる所有者の保持経験を利用するなら、受け手を固定して提供者の経験を変えると、課題に沿って応答が変わる | 提供者変更、局所記憶からの伝達遮断、通信遮断、無刺激、同時間の対照 | 提供者の内容に依存しない、または外部の答え・単なる刺激だけで説明できれば、経験共有という機構解釈を撤回する |
| H4：操作による分類は、振動子以外の指定したモデルでも容量・正答率だけでは分からない再現可能な差を示す | 事前選定した適応モデル・再帰モデルで付録の手順を実施し、追加診断の予測価値を比較 | 選定した系では既存の状態推定・制御・記憶評価と完全に重複し、実験の選択も改善しなければ、横断的研究枠組みの主張を取り下げ、振動子向けの整理へ限定する |

**立場全体への不利な条件：** 公平な予算比較で管理の利益が一貫して消え、失敗分解が介入の効果を予測せず、他のモデルにも追加の診断価値を持たないなら、独立した研究課題としてこの枠組みを押し出す根拠が乏しいと認める。

**想定される反論：** 「負の結果でも『管理が必要』と解釈できてしまう」。上記の各主張に撤回範囲を対応させる。単に有意差が出なかっただけでは反証とせず、事前の実用的な差を除外できる精度や、繰返しの範囲も示す。新しい操作を後付けして同じ予測を救済しない。

## 3. What is stored, what is observable, and who controls it?

**主張：** 記憶の所在と、それを利用する操作の所在を別々に記述する。「管理層」は機能の分類であり、中央制御器や追加の独立モジュールを必須とする名称ではない。

**使う証拠：** 公開OTB実装の単体説明 [MODEL] と、各報告の構成図・外部依存。T7作業ユニットの一実装を次で紹介する。

```text
proposed_phase = phi + omega + kappa*m
fire = (proposed_phase >= 2*pi) and (cd == 0)
m_next = (1-epsilon)*m + drive - beta*fire
phi_next = 0 if fire else proposed_phase modulo (2*pi)
cd_next = R if fire else max(cd-1, 0)
```

式はこの離散作業ユニットの更新順序を表す。MC・E・OTBの全モデルをこの式で同一視しない。結合では前stepの発火等も状態として扱う。

| 区別するもの | 本稿での意味 |
|---|---|
| 保持された履歴 | 過去の入力・活動による区別が、現在の状態またはその後の応答に残ること |
| 表出・伝達 | その区別が観測できる出力に現れ、受信側へ到達すること |
| 利用可能性 | 許された情報・操作・期限の下で、その区別を目的の行為に利用できること |
| T7内部状態m | 位相進化へ影響する履歴状態 |
| OTBの相方記憶 | 学習した関係を保持する振幅等。mだけによる長期学習とは区別 |
| eligibility e／誤差蓄積s | 更新先や更新入力に関わる補助状態 |
| 管理操作 | 読む、準備を選ぶ、更新を制御する、他者の保持経験を利用する操作 |

**想定される反論：** 「適応変数を記憶と呼び換えただけではないか」。保持の対象、時間、許される読み出し、下流での利用を測定で定義する。「回復だから記憶ではない」「T7だけが履歴を持つ」とは書かない。

**図1：** 記憶を持つ基板 → 許された読み出し → 準備・更新の操作 → 下流応答。外部の学習、オンライン制御、診断用の正解を別の線で描く。E7-D・OTB21・OTB22の三構成を並べ、どこまで内部化されているかの差を明示する。

## 4. Wall I — Retained history may be unreadable or unusable

### 4.1 保持・表出・伝達は、利用の成功を保証しない

**主張：** 読み出しの時間窓や受信側の応答特性によって、同じ発火列から利用できる履歴が変わる。

**使う証拠：** MC-4X（探索、5回路、一種類の遠近履歴課題）。混合集団のRによる主指標bothは0.531。同じ発火をRと同じ短い時間スケールで積分する外部分類器は0.546、長い積分の外部分類器は0.698 [MC4X]。bothは遠い履歴と直近履歴の二つの対比の正答率の小さい方であり、通常の全体正答率とは異なる。

**不利な証拠も同じ段落へ：** 長い積分を許すと、速い集団や結合を外した対照も同等程度に読めた。多時定数集団や記憶と運動の結合の利点が、この条件で確立したとは言わない。

**想定される反論：** 「読み出し器の容量や訓練の差ではないか」。観測量、積分時間、学習予算の違いを記す。この探索から、情報が存在しないことや時間スケール整合の普遍的必要性までは証明しない。次の同条件比較を導く材料にする。

### 4.2 「壊さずに読む」は、保存対象を定義してから使う

**主張：** 読み出しの正確さと、読み出しが将来の利用へ与える影響は別々に測る。

**使う証拠：** E7-Dは処理側Pの記憶の写しを持ち、その写しへ蹴りを与える。報告は、Pには蹴りが届かない構成と、写しの誤差を分けて確認している [E7D]。したがって本稿では「元のPへの直接の蹴りを避けた写しの読み出し」と記述する。

**想定される反論：** 「可逆な入力なら元の全状態に戻るのか」。そうは推論しない。記憶変数、位相、不応状態、発火列、後続課題のどれを保存したかを区別する。読出しあり／なしを同じ経過時間で比較する手順を付録A.2へ置く。

### 4.3 読めても、成功する準備を選べるとは限らない

**主張：** 読み出し誤差、準備の選択誤り、候補集合の不足を分けることで、次に改善する対象を特定できる。

**使う証拠：** E7-Dの確証（取得前に計画・コード・較正物を凍結、固定5回路、未使用入力群、保持条件4種）。初回を含む連続計算のうち、計算1〜7の全正答率はE7D_64で57.8%、凍結E7で48.5%。対応差は+9.3ポイント、報告の95%区間は+8.7〜+9.9ポイント [E7D] [E7PLAN] [E7RESULTS]。

区間は固定回路内の群を再標本化したもの。5回路を新しい回路母集団の代表として扱う推論とは区別する。二候補の外部解析選択ANA2は60.7%であり、E7D_64がそれを上回ったわけではない。

失敗の記述分析では、計算1〜7の107,520回中、E7D_64の失敗は11,194回。そのうち10,148回（90.7%）は、到達したその状態で二候補のどちらも成功できなかった。これは全状態の90.7%でも、あらゆる操作による成功が不可能という意味でもない [E7RESULTS]。

**不利な証拠：** 16素子から64素子への変更による全7成功率の差は小さく、報告の区間はゼロを含む。読み出しの規模拡大が、同じだけ連続計算を改善するとは言えない [E7D]。

**想定される反論：** 「候補不足と分かったのは正解を知るoracleがあるからでは」。その診断は評価専用と明記する。有限候補が全て失敗したことと、全制御空間で不可能なことを区別する。また各方策が異なる状態へ到達するため、失敗構成の差をそのまま方策間の因果効果にしない。

**節の着地点：** 保持する → 表出する → 伝える → 保存条件を明示して読む → 準備を選ぶ。これらは連鎖する操作だが、それぞれに失敗の可能性がある。

## 5. Wall II — Learning something new may corrupt what is retained

**主張：** 学習則を固定した系では、更新のタイミングや残存する活動痕跡が、獲得と保持の両立を左右する。「門を守る」は、単に書込みを止めることではなく、必要な更新を許しながら既存記憶への影響を制御することとして定義する。

**使う証拠：** OTB21は、以前の問い合わせのeligibilityが残った状態で次の経験を与える課題。待機は次の問い合わせの前に入り、外部guardがe/sを読む。E7-Dの振動子読み出しをそのまま用いたものではない [OTB21]。

| 問い合わせ1536 step、各128条件 | 新文脈に正答 | 旧operationの両文脈に正答 | 平均総live時間 |
|---|---:|---:|---:|
| 追加待ちなし | 128/128 | 64/128 | 14,632 step |
| 固定4096 step待ち | 128/128 | 64/128 | 18,728 step |
| 状態に基づくguard | 128/128 | 128/128 | 30,040.25 step |

確認範囲は8記憶seed×4位相×2旧文脈×2新文脈。128の独立した世界や128種類の規則ではない。正答は学習後の記憶コピーを標準状態から診断したもの。総live時間に診断用コピーの計算は含まれない。全3問い合わせ時間・3方式で1,152試行 [OTB21]。

**同じ節に置く不利な証拠：**

- OTB21の最長問い合わせ4096 stepでは、固定待ちでも獲得・保持の両方が128/128。guardは十分条件であり、最短待機条件ではない。
- 時間を合わせた固定待ちに対する優位は未確立。問い合わせ期限と書込み開始時刻が同時に変わるので、期限だけの効果とも言えない。
- OTB20の探索では、誤差振幅を制限した各32条件の非対象保持は32/32だった一方、対象更新は0/32。保護だけを採点すると、学習できない系を高評価してしまう [OTB20]。

**想定される反論：** 「長く待ったから成功しただけでは」。その説明は排除できていないと明記する。待機時間を広く調整した固定方策、状態を用いない同じ待機分布、状態依存方策を、総期限と観測費用を含めて比較することを次の検証にする。

**節の着地点：** 新規獲得、旧記憶保持、両立、時間・活動費用を同時に示す。保持成功のみを管理機構の成功にしない。

## 6. Wall III — Experience held elsewhere may remain inaccessible

**主張：** 自分の系だけでは利用できない関係を、別の所有者が保持する経験と接続して利用できるかは、単体の記憶保持とは別の実験課題になる。

**使う証拠：** OTB22の機構試験。3所有者がA→B、B→C、C→Dを別々に保持し、同一対象の作業T7の発火を接続する。8位相×2座標表示の16条件で、受け手への支持応答は共有あり16/16、共有なし0/16。必要な局所記憶から作業群への伝達遮断は0/48、所有者間接続の遮断は0/32 [OTB22]。

**分類：** pilotを経て取得前に設定を固定した機構試験と、その記述分析。E7-Dと同じ形式の確証実験とは呼ばない。16条件は同一の論理鎖を異なる位相・表示で試したもので、16の独立した意味世界ではない。

**不利な証拠：**

- 先行pilotは、不要な支持や残留活動を生み、元の全通過条件を満たさなかった。その失敗を残す。
- 本取得では復元なしでも停止し、追加の復元や共有線閉鎖の必要性・優位は示されなかった。管理操作を増やすほどよい、という物語にしない。
- 対立する経験が共存してもネットワークは支持応答を出した。矛盾検知や自動保留は未達。
- 所有者・対象の同一性、接続先、文脈、刺激開始時刻は与えられる。共有中の受け手への学習はない。局所記憶への帰還がないので、同時間の共有有無で記憶が一致することは構造上予測される。

**想定される反論：** 「普通のグラフ探索でも解ける」。その通りであり、振動子方式の優位は示していない。「分かち合う」はここでは接続中の共同読出しを指す。経験の獲得、意味の自動対応、受け手の学習、実ネットワーク通信は分けて評価する。

**節の着地点：** 共有を、コピー、接続中の利用、受け手への学習、矛盾の扱いに分ける。今回確認したのは、そのうち限定された接続中の利用である。

## 7. Division of roles, adverse evidence, and related research

### 7.1 記憶を持つ素子が、中継にも適するとは限らない

**主張：** 記憶保持、信号伝達、判断に必要な特性は異なり得る。どの役割も同じ素子で担えるという仮説を採用しない。役割分担も、課題と費用の下で検証する設計候補として扱う。

**使う証拠：** MC-5Cは、T7記憶集団→遅い／速いLIF中継→出力Rという構成を未使用20回路で評価した確証。LIF中継の主指標bothは0.707。片方の中継を除いて重みを選び直す対照や役割入れ替えを含む [MC5C]。

**T7に不利な結果を明示：** 同じ不応期32の副次比較では、LIF中継のbothは0.698、T7中継は0.508。保存集計の丸め前の対応差T7−LIF32は−0.189で、報告の95%区間は−0.201〜−0.178。20回路すべてでT7側が低かった。ただし、この比較は発火率を一致させていない [MC5C] [MC5CDATA]。

MC-5Dは探索用の別の5回路で、検証時の発火率を目標の±20%へ制約し、3水準を比較した探索。3水準ともLIF中継がT7中継を上回った。発火率を厳密に等しくした比較、全動作点の最適化、確証の追試とは記さない。負の位相をクリップした別素子の診断でも、差は大きく解消しなかった [MC5D]。

**解釈の境界：** この結果はT7の中継適性に不利である。T7を記憶集団に使う必要性や優位性を支持する比較ではない。記憶集団までLIF等へ置き換えた対照が必要になる。LIFとT7の混成回路の成功を、T7単独の成功として紹介しない。

**想定される反論：** 「ならばすべて既存方式でよいのでは」。その可能性も比較対象にする。固定した履歴依存基板を制御する問いは残るが、それだけで振動子方式を採用する利益が示されたことにはならない。

### 7.2 学習可能な更新則との比較

**主張：** 管理機能は学習済みの更新則に内包されることもある。明示した管理層が全モデルに必須とは言わない。

**使う証拠：** E3bの報告は、強化した学習手順で一部のGRUがリセットなしの連続課題を解いたことを示す。全モデルで学習に成功したわけではなく、T7と学習対象・時間分解能も異なる [E3B]。本稿では、学習可能な更新則によって別の解法を得られる参照例として取り上げる。E7-Dとの新しい同条件比較にはしない。

**想定される反論：** 「管理とはゲートや制御の別名では」。名称の新しさを貢献にせず、何を利用可能にし、何を損ない、どの費用を要したかという共通の測定へ接続する。

**主張：** 既存研究との関係を、過去を保持する場所、許される読み出し、更新の制御、観測と行為の時間スケールで比較する。

**使う証拠：** 以下は本文執筆前に一次文献を照合する項目であり、現段階で新規性の比較を完了したという意味ではない。

## 8. Research agenda and conclusion

**主張：** 次に増やすべきものは成功例の列挙だけではなく、利用を妨げる原因を切り分け、操作の利益と費用を比較できる実験である。

**使う証拠：** 第4〜7節の成功と不利な結果から、次の検証へ結びつける。

| 次の研究 | 最小の比較 | 判断するもの |
|---|---|---|
| 読み出しと候補集合の寄与 | 同一状態から読み出し改善／候補変更／両方／変更なし | どの失敗要因がどれだけ減るか、費用増で説明されるか |
| 更新と保持の費用 | 調整した固定待ち／状態を使わない待機／状態依存guard | 同じ総期限での新規獲得・旧保持・両立 |
| 記憶と中継の役割 | 記憶群と中継の素子を別々に置換し再較正 | T7が必要・有利な役割があるか、混成の利益が残るか |
| 共有と学習の分離 | 接続中／切断後、受け手更新あり／なし | 他者の応答の利用と、受け手自身への学習の違い |
| 診断の移植性 | 事前選定した異なる基板に同じ診断を適用 | 分解が新条件の介入効果を予測するか |

**想定される反論：** 「対象が広すぎて検証不能では」。最初は固定基板の小規模課題群に限定する。診断の移植性は独立した仮説として試す。規模を増やせば管理が不要／必要になるという結論を先取りしない。

**結論に置くメッセージ：** 記憶が存在することを確かめたら、次に、その記憶を利用可能にしている観測と操作、費用、失敗条件を明示する。読者は付録の手順を自分の系へ持ち帰れる。

## Appendix A. A reader's protocol for testing usable memory

**主張：** 異なるモデルでも、保持、読み出し、選択、更新干渉を別々に診断できるようにする。共通の万能スコアは作らず、操作条件と費用を添えた測定表を得る。

**使う証拠：** MC-4Xの時間スケール、E7-Dの失敗分解、OTB20/21の獲得と保持、OTB22の伝達遮断を、モデルに依存しない手順へ翻訳する。以下は提案手順であり、全項目が既存系列で実行済みという意味ではない。

**想定される反論：** 「状態のコピーや正解oracleを用意できないモデルでは使えない」。シミュレーションの分岐比較と実機の反復試行を区別する。実施できない介入や不明な到達可能性は未測定として残し、推測で埋めない。

### A.0 共通の準備

1. **利用したい過去を定義する。** 例：ある入力が過去の窓に存在したか、以前学習した関係は何か。履歴ラベルと将来課題の正解を分ける。
2. **許される情報と操作を列挙する。** 内部状態を直接読めるか、発火のみか。操作候補、期限、観測時間、学習対象、リセット箇所を記録する。評価者だけが使う情報は別欄に置く。
3. **分割を固定する。** 較正、モデル選択、評価を履歴・入力系列単位で分ける。同一回路の新入力と新回路を別に報告する。探索で選んだ設定を確証で選び直さない。
4. **対照と採点を凍結する。** 無履歴、固定行為、同時間の待機、診断用の完全情報参照などから必要なものを選ぶ。クラス比率と自明方策の成績を記す。
5. **資源を数える。** 観測、準備、通信、復元、更新、外部読み出しを含める。native step、実時間、メモリ量、発火数を混同せず、未測定のエネルギーは主張しない。

### A.1 保存 — 過去の何が、どれだけ残るか

**読者への問い：** 現在の入力を同じにしても、異なる過去を区別できるか。その区別はどの状態・時間に残るか。

1. 過去だけが異なる対応した履歴群を作り、その後の入力と待機時間を合わせる。
2. 複数の遅延で状態または許された観測を記録する。位相や現在入力などの手掛かりで履歴ラベルを当てられないようにする。
3. 較正データだけで診断用の復号器を学習し、未使用履歴で評価する。クラス不均衡がある場合はクラス別成績・balanced accuracy等を併記する。
4. ラベルの置換、履歴なし対照、可能なら履歴を担う経路への介入と比較する。状態の直接置換が通常軌道外の状態を作る場合は、自然な履歴から到達した状態による対照を優先する。
5. 遅延ごとの復号成績、採用した復号器、観測時間・次元・学習予算を記す。

**記録するもの：** 履歴区別の成績対遅延、対照との差、回路・履歴の数、区間の再標本化単位。

**解釈：** 復号成功は、その観測と復号器が情報を利用できた証拠。復号失敗だけでは、系に情報が存在しないとは言えない。下流の実行器による利用はA.2/A.3で測る。

### A.2 読み出し — 読めるか、読んだ後にも使えるか

**読者への問い：** 実際に許される読み出しで必要な区別を得られるか。読み出しによって何が変わるか。

1. A.1と同じ履歴から、診断用の完全状態参照と、実行時に許された読み出しを別々に評価する。
2. 同じ開始状態から「読出しあり」「同時間経過・読出しなし」「必要なら同じ介入量で情報を使わない対照」を比較する。確率系は共通乱数による対応比較と、独立反復での頑健性を分ける。
3. 両枝を**同じ終了時刻**に合わせ、記憶・位相・不応状態等の差と、同じ後続課題への応答差を測る。
4. 読出しを繰り返し、誤差や影響の蓄積を調べる。写しを用いる場合は、その作成・維持誤差と費用も含める。
5. 「非破壊」と呼ぶ対象と許容幅を取得前に決める。状態の完全一致、保存内容の一致、課題性能の許容差は別の基準にする。

**記録するもの：** 復号誤差、読み出し時間、状態差、後続課題の損失、反復回数に伴う変化。実機で同一状態の複製ができなければ、同じ履歴生成条件による反復とその不確実性を報告する。

### A.3 選択 — 判断が悪いのか、成功できる操作がないのか

**読者への問い：** 成功できる候補が存在したのに選び損ねたのか。その状態では、用意した候補の全てが失敗したのか。

1. 実行可能な候補集合Aと成功条件・期限を固定する。各候補に観測・待機の費用も含める。
2. 同じ開始状態から各候補を分岐評価して、評価専用の成功集合を作る。これをオンライン選択器へ渡さない。複製不能な系では対応する履歴の反復推定を使う。
3. 成功候補の存在率、存在するときの選択失敗率、全判断に占める選択失敗率を、分母を分けて集計する。
4. 完全状態から同じ判断規則を動かした診断枝と、実際の読み出しを使った枝を比べ、読み出し誤差が選択・結果を変えた割合を測る。診断による原因推定と、実際に読み出しを改良した介入の効果を分ける。
5. 成功候補を選んでも失敗する例は、実行時のずれ、確率性、予測器の誤り等として別に記録する。
6. 読み出し改善と候補集合の変更を別々に試す。候補探索・生成の追加費用を含めて比較する。

**決定論的な場合の指標例：**

```text
Y_i(a) = 状態iから候補aを実行した場合の成功（評価専用）
E_i = max_{a in A} Y_i(a)

成功候補の存在率 = sum(E_i) / 判断数
条件付き選択失敗率 = sum(E_i * (1 - Y_i(選択候補))) / sum(E_i)
全判断中の選択失敗率 = sum(E_i * (1 - Y_i(選択候補))) / 判断数
```

sum(E_i)=0なら条件付き失敗率は未定義と記す。確率系では候補ごとの成功確率を反復推定し、取得前に定めた基準と不確実性を使う。一度の幸運な成功を到達可能性としない。

**解釈：** 候補を全列挙していない場合は、最良の試行を厳密な上限と呼ばない。全候補失敗でも「この集合・期限では成功なし」であり、不可能と未知を区別する。方策間の比較は同一状態からの診断と、各方策の連続運用の両方を示す。

### A.4 更新干渉 — 学べたか、守れたか、同時にできたか

**読者への問い：** 新しい経験で対象を変えたとき、変更しないはずの記憶は保たれるか。保護のために学習自体が止まっていないか。

1. 更新対象の課題と、変更しない旧課題を分け、更新前に両方を測る。読出しが状態を変える場合は別の診断枝を使う。
2. 旧課題の使用が残す履歴を、制御した条件で引き継いでから新しい経験を与える。履歴生成と自然運用からの採取は区別する。
3. 更新なし、即時更新、調整済みの固定待機、状態依存の更新制御を同じ経験系列で比較する。固定待機の較正予算を確保し、総期限を合わせた比較も必ず設ける。
4. 新課題の獲得、旧課題の保持、両方が成立する試行数を別々に測る。旧課題の使用有無や残存traceへの介入で干渉の原因を調べる。
5. 更新後の即時診断と、状態を引き継ぐ後続運用での成績を分ける。標準状態へ戻した診断結果を、連続運用の成功に読み替えない。
6. 時間予算を変え、獲得・保持・総時間の関係を示す。外部の観測と比較器、教師誤差、診断枝の費用を区別して報告する。

**記録するもの：** 新規獲得率、旧記憶保持率、同一試行での両立率、総時間、更新回数、活動量。連続スコアの場合は変化量も記す。「更新しないので忘れない」という対照を成功扱いしない。

### A.5 共有を扱う読者への追加手順

1. 受け手の初期状態と入力を固定し、提供者の保持内容だけを変える。
2. 共有なし、必要な所有者からの伝達遮断、接続遮断、無刺激、時間を合わせた対照を置く。
3. 接続中の改善と、切断後に受け手へ残った変化を分ける。後者だけを受け手の学習候補とする。
4. 相反する経験を与え、支持・否定・保留を事前定義して測る。無発火を自動的に否定と解釈しない。
5. 対象の同一性、接続、問い合わせの指定、正解の経路を誰が与えたか記録する。

### A.6 読者が持ち帰る報告シート


**元骨子から今回採用しない数値・表現：**

- 読み出しの「4→64素子、78.4%→94.1%、上限約96%」は、今回その定義と元集計を照合していないため使わない。確証の93.8%等と混ぜない。
- 「選択失敗1.8%」を条件付きの誤選択率として使わない。E7-Dの保存集計では、成功候補がある場合と全判断に対する指標が別である。本稿の中心例には分母が明確な失敗内訳を採用する。
- 「最軽量クラス」「他人が真似できない」「単位が増えても質的跳躍は起きない」「LIFは履歴を持たない」は使わない。
- OTB0〜4・OTB13を個別の実証根拠として追加する場合は、その版・構成・結果を別途照合する。動詞に番号を機械的に割り当てない。
