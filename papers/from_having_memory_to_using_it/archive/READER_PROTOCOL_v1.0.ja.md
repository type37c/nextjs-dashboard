# Reader Protocol — From Having Memory to Using It

## Appendix A. A reader's protocol for testing usable memory

**主張：** 異なるモデルでも、保持、読み出し、選択、更新干渉を別々に診断できるようにする。共通の万能スコアは作らず、操作条件と費用を添えた測定表を得る。

**使う証拠：** MC-4Xの時間スケール、E7-Dの失敗分解、OTB20/21の獲得と保持、OTB22の伝達遮断を、モデルに依存しない手順へ翻訳する。以下は提案手順であり、全項目が既存系列で実行済みという意味ではない。

**想定される反論：** 「状態のコピーや正解oracleを用意できないモデルでは使えない」。シミュレーションの分岐比較と実機の反復試行を区別する。実施できない介入や不明な到達可能性は未測定として残し、推測で埋めない。

### A.0 共通の準備

1. **利用したい過去を定義する。** 例：ある入力が過去の窓に存在したか、以前学習した関係は何か。履歴ラベルと将来課題の正解を分ける。
2. **許される情報と操作を列挙する。** 内部状態を直接読めるか、発火のみか。操作候補、期限、観測時間、学習対象、リセット箇所を記録する。評価者だけが使う情報は別欄に置く。
3. **分割を固定する。** 較正、モデル選択、評価を履歴・入力系列単位で分ける。同一回路の新入力と新回路を別に報告する。探索で選んだ設定を確証で選び直さない。
4. **対照と採点を凍結する。** 無履歴、固定行為、同時間の待機、診断用の完全情報参照などから必要なものを選ぶ。クラス比率と自明方策の成績を記す。
5. **資源を数える。** 観測、準備、通信、復元、更新、外部読み出しを含める。native step、実時間、メモリ量、発火数を混同せず、未測定のエネルギーは主張しない。

### A.1 保存 — 過去の何が、どれだけ残るか

**読者への問い：** 現在の入力を同じにしても、異なる過去を区別できるか。その区別はどの状態・時間に残るか。

1. 過去だけが異なる対応した履歴群を作り、その後の入力と待機時間を合わせる。
2. 複数の遅延で状態または許された観測を記録する。位相や現在入力などの手掛かりで履歴ラベルを当てられないようにする。
3. 較正データだけで診断用の復号器を学習し、未使用履歴で評価する。クラス不均衡がある場合はクラス別成績・balanced accuracy等を併記する。
4. ラベルの置換、履歴なし対照、可能なら履歴を担う経路への介入と比較する。状態の直接置換が通常軌道外の状態を作る場合は、自然な履歴から到達した状態による対照を優先する。
5. 遅延ごとの復号成績、採用した復号器、観測時間・次元・学習予算を記す。

**記録するもの：** 履歴区別の成績対遅延、対照との差、回路・履歴の数、区間の再標本化単位。

**解釈：** 復号成功は、その観測と復号器が情報を利用できた証拠。復号失敗だけでは、系に情報が存在しないとは言えない。下流の実行器による利用はA.2/A.3で測る。

### A.2 読み出し — 読めるか、読んだ後にも使えるか

**読者への問い：** 実際に許される読み出しで必要な区別を得られるか。読み出しによって何が変わるか。

1. A.1と同じ履歴から、診断用の完全状態参照と、実行時に許された読み出しを別々に評価する。
2. 同じ開始状態から「読出しあり」「同時間経過・読出しなし」「必要なら同じ介入量で情報を使わない対照」を比較する。確率系は共通乱数による対応比較と、独立反復での頑健性を分ける。
3. 両枝を**同じ終了時刻**に合わせ、記憶・位相・不応状態等の差と、同じ後続課題への応答差を測る。
4. 読出しを繰り返し、誤差や影響の蓄積を調べる。写しを用いる場合は、その作成・維持誤差と費用も含める。
5. 「非破壊」と呼ぶ対象と許容幅を取得前に決める。状態の完全一致、保存内容の一致、課題性能の許容差は別の基準にする。

**記録するもの：** 復号誤差、読み出し時間、状態差、後続課題の損失、反復回数に伴う変化。実機で同一状態の複製ができなければ、同じ履歴生成条件による反復とその不確実性を報告する。

### A.3 選択 — 判断が悪いのか、成功できる操作がないのか

**読者への問い：** 成功できる候補が存在したのに選び損ねたのか。その状態では、用意した候補の全てが失敗したのか。

1. 実行可能な候補集合Aと成功条件・期限を固定する。各候補に観測・待機の費用も含める。
2. 同じ開始状態から各候補を分岐評価して、評価専用の成功集合を作る。これをオンライン選択器へ渡さない。複製不能な系では対応する履歴の反復推定を使う。
3. 成功候補の存在率、存在するときの選択失敗率、全判断に占める選択失敗率を、分母を分けて集計する。
4. 完全状態から同じ判断規則を動かした診断枝と、実際の読み出しを使った枝を比べ、読み出し誤差が選択・結果を変えた割合を測る。診断による原因推定と、実際に読み出しを改良した介入の効果を分ける。
5. 成功候補を選んでも失敗する例は、実行時のずれ、確率性、予測器の誤り等として別に記録する。
6. 読み出し改善と候補集合の変更を別々に試す。候補探索・生成の追加費用を含めて比較する。

**決定論的な場合の指標例：**

```text
Y_i(a) = 状態iから候補aを実行した場合の成功（評価専用）
E_i = max_{a in A} Y_i(a)

成功候補の存在率 = sum(E_i) / 判断数
条件付き選択失敗率 = sum(E_i * (1 - Y_i(選択候補))) / sum(E_i)
全判断中の選択失敗率 = sum(E_i * (1 - Y_i(選択候補))) / 判断数
```

sum(E_i)=0なら条件付き失敗率は未定義と記す。確率系では候補ごとの成功確率を反復推定し、取得前に定めた基準と不確実性を使う。一度の幸運な成功を到達可能性としない。

**解釈：** 候補を全列挙していない場合は、最良の試行を厳密な上限と呼ばない。全候補失敗でも「この集合・期限では成功なし」であり、不可能と未知を区別する。方策間の比較は同一状態からの診断と、各方策の連続運用の両方を示す。

### A.4 更新干渉 — 学べたか、守れたか、同時にできたか

**読者への問い：** 新しい経験で対象を変えたとき、変更しないはずの記憶は保たれるか。保護のために学習自体が止まっていないか。

1. 更新対象の課題と、変更しない旧課題を分け、更新前に両方を測る。読出しが状態を変える場合は別の診断枝を使う。
2. 旧課題の使用が残す履歴を、制御した条件で引き継いでから新しい経験を与える。履歴生成と自然運用からの採取は区別する。
3. 更新なし、即時更新、調整済みの固定待機、状態依存の更新制御を同じ経験系列で比較する。固定待機の較正予算を確保し、総期限を合わせた比較も必ず設ける。
4. 新課題の獲得、旧課題の保持、両方が成立する試行数を別々に測る。旧課題の使用有無や残存traceへの介入で干渉の原因を調べる。
5. 更新後の即時診断と、状態を引き継ぐ後続運用での成績を分ける。標準状態へ戻した診断結果を、連続運用の成功に読み替えない。
6. 時間予算を変え、獲得・保持・総時間の関係を示す。外部の観測と比較器、教師誤差、診断枝の費用を区別して報告する。

**記録するもの：** 新規獲得率、旧記憶保持率、同一試行での両立率、総時間、更新回数、活動量。連続スコアの場合は変化量も記す。「更新しないので忘れない」という対照を成功扱いしない。

### A.5 共有を扱う読者への追加手順

1. 受け手の初期状態と入力を固定し、提供者の保持内容だけを変える。
2. 共有なし、必要な所有者からの伝達遮断、接続遮断、無刺激、時間を合わせた対照を置く。
3. 接続中の改善と、切断後に受け手へ残った変化を分ける。後者だけを受け手の学習候補とする。
4. 相反する経験を与え、支持・否定・保留を事前定義して測る。無発火を自動的に否定と解釈しない。
5. 対象の同一性、接続、問い合わせの指定、正解の経路を誰が与えたか記録する。

### A.6 読者が持ち帰る報告シート

```text
モデル／版／コードとデータの参照：
対象とする履歴と課題：
固定した更新則／学習できるパラメータ：
実行時に許される観測・操作／評価者だけの情報：
履歴・入力・モデルの訓練／検証／評価分割：
保存：何を、どの遅延で、どの復号器が区別できたか：
読み出し：誤差、時間、保存対象、後続応答への影響：
選択：候補集合、存在率、条件付き失敗率、各分母：
更新：新規獲得、旧保持、同時成立、継続運用での結果：
共有（該当する場合）：接続中の利用／切断後の保持：
費用：観測・待機・準備・通信・更新・外部計算：

未測定・識別できない原因・次の介入：
証拠区分：探索／取得前固定の評価／確証の主判定／副次分析：

```
