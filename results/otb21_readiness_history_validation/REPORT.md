# OTB21：位相と期限を変えた最終境界評価

2026-11-05。OTB19の安全条件と、OTB20の探索から選んだ固定待ちを、追加の位相・期限条件へ適用した。新しい結果を見た後のパラメータ変更は行っていない。

**短い固定待ちは、問い合わせ時間を短くした条件で、既存記憶の巻き込みを防げなくなった。保持条件から導いたguardは、今回の全条件で新しい文脈の学習と既存記憶の保持を両立した。ただし、追加の待ち時間が大きい。**

## 変えた条件と、固定した条件

OTB15の保持後の8 seedの記憶を使い、作業T7の初期位相を新たな4 draw（RNG 27501）へ変えた。4 drawは全seedで共通。初期m=-1.2、不応状態512、直前発火0は固定した。これは宣言した合成初期条件であり、自然な運用履歴からの無作為標本ではない。

古いoperation 1の文脈を一度、ラベルなしで問い合わせた後、その全状態を継承する。続いてoperation 0の文脈を問い合わせ、反転した結果を一度だけ与える。古い文脈2種類、新しい文脈2種類をすべて組み合わせた。

現在の問い合わせ時間は1,536 / 2,048 / 4,096 step。128 stepの作業準備、1,000 stepの結果遅延、8,000 stepの書込みは固定した。比較は追加待ちなし、固定4,096 step待ち、OTB19と同じ式・閾値のguard。新しいモデル式、痕跡の直接クリア、ラベルを使う準備選択は導入していない。

8 seed × 4位相 × 2旧文脈 × 2新文脈 = 128条件／問い合わせ時間・方式。全体は1,152学習試行である。

## 学習後の応答と、既存記憶の保持

以下の正答は、学習後の記憶のコピーを標準の作業状態から診断した値。診断後の状態や正解はlive学習へ戻していない。未観測のもう一つのoperation 0文脈まで変更できたとは扱わない。

| 現在の問い合わせ時間 | 方式 | 今回教えた文脈に正答 | 無変更operation 1の両文脈に正答 | 両方を満たす |
|---:|---|---:|---:|---:|
| 1,536 | 待ちなし | 128 / 128 | 64 / 128 | 64 / 128 |
| 1,536 | 固定4,096待ち | 128 / 128 | 64 / 128 | 64 / 128 |
| 1,536 | guard | 128 / 128 | 128 / 128 | 128 / 128 |
| 2,048 | 待ちなし | 128 / 128 | 64 / 128 | 64 / 128 |
| 2,048 | 固定4,096待ち | 128 / 128 | 64 / 128 | 64 / 128 |
| 2,048 | guard | 128 / 128 | 128 / 128 | 128 / 128 |
| 4,096 | 待ちなし | 128 / 128 | 64 / 128 | 64 / 128 |
| 4,096 | 固定4,096待ち | 128 / 128 | 128 / 128 | 128 / 128 |
| 4,096 | guard | 128 / 128 | 128 / 128 | 128 / 128 |

無変更operation 1の振幅記憶帯を保持した件数も、対応する正答数と一致した。各群で現在のsourceは128/128件で刺激後に発火し、結果ラベル前の予測に保留はなかった。したがって、今回の不成功を「新しい入力がタグ付けされなかった」と説明することはできない。

## 安全条件と時間の費用

guardの待ち時間は、以前の固定履歴の15,080 stepから、今回の4位相では15,131 / 15,364 / 15,563 / 15,575 stepへ変化した。平均は15,408.25 step。痕跡の状態に応じて必要待ちが変わったが、最適な固定待ちへの優位を示す比較ではない。

| 現在の問い合わせ時間 | 待ちなし：平均総live時間 | 固定待ち：平均総live時間 | guard：平均総live時間 |
|---:|---:|---:|---:|
| 1,536 | 14,632 | 18,728 | 30,040.25 |
| 2,048 | 15,144 | 19,240 | 30,552.25 |
| 4,096 | 17,192 | 21,288 | 32,600.25 |

単位はnative step。古い問い合わせ、新しい問い合わせ、追加待ち、結果遅延、書込みを含む。診断用コピーの計算はlive時間へ含めない。方式間で総時間が同じ比較ではないため、安全性と費用を両方示す。

guardでは、実際の書込み開始時の非現在セルの傾き入力上界は、1,536 / 2,048 / 4,096条件で最大0.27733 / 0.26283 / 0.21574だった。すべて保持帯の閾値0.38490未満だった。一方、固定4,096待ちの最長問い合わせ条件では上界が閾値を超えても保持できた。guardは十分条件であり、最短必要待ちを与える式ではない。

事前指定した1,536 step条件の通常・guard各1試行では、古い問い合わせから書込みまでの全時刻を保存した。通常の非現在セル入力の最大絶対値は1.69579で記憶帯を離れ、guardは最大0.22202で全時刻に帯を保持した。全1,152試行の全時刻を独立実装で再現したという意味ではない。

## 読み取れる範囲

この評価は、既存の4つの二値文脈と、保存済み記憶を使う追加入力条件の試験である。新しい意味規則・概念・実機・大規模環境への確証ではない。4位相の繰返しを独立した規則の増加として数えない。

問い合わせ期間を短くすると結果を届ける時刻も早まり、古い活動履歴の減衰時間が減る。問い合わせ期限と学習開始時刻を同時に変えた試験であり、期限だけの影響を分離した実験ではない。

支持されたのは、この固定された学習則で、以前の活動の痕跡が十分に弱まってから次の活動と結果を与えると、問い合わせ期限を変えても、今回試した範囲では変更しない記憶を保てること。固定待ちの経験的な成功条件がそのまま別の期限へ移るとは限らないことも分かった。

guardは `e/s` を直接読む外部比較器であり、E7-Dの振動子読み出しそのものではない。スループットや省電力の優位も未実証。より短い待ちを使うには、保持条件だけでなく、有限の書込み時間と入力強度を含む条件が必要になる。
